# /backfill-knowledge — give an existing repo its knowledge layer

Triggered by: `/backfill-knowledge`

A repo Rigel adopted has the harness but no `knowledge/`. This fills it — **without inventing
anything a machine cannot prove.**

---

## Step 0 — Precondition

The anchor checker's library is stamped in at scaffold/adopt/update time, not shipped in the
template. Without it `npm run knowledge` cannot run, so a glossary written now would be unverifiable
prose:

```bash
test -f scripts/lib/rigel-knowledge-lib.mjs || { echo "BLOCK: run \`npx create-rigel adopt\` first"; exit 1; }
```

---

## The rule: derive what an anchor can prove, ask for everything else

| Artifact | | Why |
|---|---|---|
| `.rigel/service.json` | **derive** | `create-rigel facts` reads only existing artifacts — the OpenAPI spec, `docker-compose.yml`, `.env.example`. Nothing is guessed. |
| Glossary candidates + `anchors:` | **derive** | An anchor's entire job is to be mechanically resolvable, and you prove it by running the checker. |
| The definition sentence | **ASK** | The point of a glossary is the business meaning, which the code does not contain. `Shipment` the class is not `Shipment` the domain term; a machine can only restate the code, which produces a wiki nobody reads. |
| `owner:` | **ASK** | A wrong owner makes every *other* repo silently **skip** that anchor. A guessed owner is a false green with cross-repo reach. |
| `kpi`, `revenue_link`, capabilities | **ASK** | No artifact in a codebase encodes revenue linkage, and a guessed KPI is printed as fact in `create-rigel impact`'s BUSINESS line. Same doctrine as a spec's `breaking:` field: **the tool never fills it in silently, because a machine-written declaration verifies nothing.** |
| `knowledge/map/services.json` | **never write** | Generated by `create-rigel map:build` from the layer. |

> If you cannot get an answer to an ASK item, **leave the entry out**. A missing term costs less
> than a wrong one, and a wrong `owner:` costs the most of all.

---

## Step 1 — Derive the service facts

```bash
npx create-rigel facts
```

Show the output. It is derived, so it needs no review beyond "does this look like your service?"

## Step 2 — Get the candidate terms

```bash
npx create-rigel candidates
```

Read-only, ranked by domain layer then fan-in, and every symbol is one the anchor checker can
already resolve. **Do not grep for terms yourself** — the ranking exists so the proposal is
reproducible rather than improvised.

## Step 3 — Ask, one term at a time

For each candidate, ask the human:

```
<Symbol>  (defined in <file>)
  1. In one sentence, what does this mean to the BUSINESS — not to the code?
  2. Which service owns the definition?  (blank = this repo)
```

**Stop and wait.** Do not fill in a default. If the human skips a term, drop it.

Write only the answered ones, at most **10** in this pass:

```markdown
---
term: Bookmark
owner: acme-bookmarks          # omit entirely if this repo owns it
anchors:
  - symbol: Bookmark
---

<their sentence, not yours>
```

## Step 4 — Prove every anchor resolves

```bash
npm run knowledge
```

**Delete any entry whose anchor fails.** A stale anchor on day one teaches everyone the check is
noise, and a glossary the checker rejects is worse than no glossary.

## Step 5 — The bounded context (optional, ask first)

`knowledge/domain/contexts/<service>.md` is prose with no frontmatter. Derive the structural half
(routes, models, deps from `.rigel/service.json`); ask for the "why this exists" half. Do not commit
it until that half is answered.

## Step 6 — Capabilities

If `.rigel/manifest.json` has a `layer`, business capabilities belong to the **layer**, not here.
Print the block for the human to paste there and write nothing locally.

Otherwise ask for capability, owner and KPI, and only then write
`knowledge/business/capabilities/<name>.md`.

## Step 7 — Report

```
knowledge/ backfilled:
  <n> glossary terms, all anchors resolving
  <n> terms skipped (no business definition given)
  service facts: .rigel/service.json

Run `npx create-rigel doctor` to see what's left.
```
