## Goal

Ship the `/bookmarks` route: a server-component page rendering a `BookmarkList` client feature
that reads data through a `useBookmarks` TanStack Query hook over the typed api-client — with
loading (skeleton), empty, and error states, styled with design tokens only.

---

## Pre-Build Step

`src/types/api.generated.ts` was generated by `/api-sync` from `openapi.json`
(`GET /api/v1/bookmarks` → `{ items, has_more, next_cursor_id }`). Contract is current.

---

## Layer Build Order

- [x] Layer 3: Hooks — `src/hooks/use-bookmarks.ts` (TanStack Query over apiClient; query keys; error handling)
- [x] Layer 5: Features — `src/features/bookmarks/bookmark-list.tsx` (`'use client'`: list + skeleton + empty + error; tokens only; a11y)

## Acceptance Criteria

- [x] AC-1: visiting `/bookmarks` renders a list whose items come from the `useBookmarks` hook (MSW-mocked).
- [x] AC-2: no component/feature/page calls `fetch()` directly — all data flows through `src/hooks/`.
- [x] AC-3: while pending a skeleton is shown; when empty an empty-state message is shown.
- [x] AC-4: the rendered `/bookmarks` page passes design-token conformance (no off-token values).
